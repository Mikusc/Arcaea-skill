# Arcaea 更新情报编辑规则

准备或人工复核草稿时读取本文件。

## 分组

- 来源按发布时间从旧到新排列。
- 优先用明确版本号和同一主题分组；同主题的无版本动态只能并入唯一的版本组。
- 仅凭最近发布时间合并属于低置信度行为，必须保留 `nearest_version_by_time` 并进入人工复核。
- 一个组出现多个版本号时不得自动发布。
- 不把周边、直播、壁纸、商品或实体专辑混入更新情报；例外通过 workspace rules 或本轮 `--keyword` 明确加入。
- 未来版本使用新措辞时优先更新 `arcaea_update_rules.json`，不要为单个案例累积硬编码分支。

## 标题与正文

- 腾讯标题字段保存完整标题；正文不重复顶层 `#` 标题。
- 删除 Bilibili 话题标签，不改写版本号、日期、曲名、搭档名或活动条件。
- 同一来源的文字后紧跟该来源图片占位符；不同来源用 `---` 分隔。
- 不把所有文字和所有图片分别堆在两端。
- 来源用内联 Markdown 链接 `[原动态 N](https://t.bilibili.com/...)`，不放裸 URL。
- 多个来源中的相同图片只上传一次；manifest 必须记录图片归属来源、占位符索引与 SHA-256。

## 图片

- 优先使用动态原图，不生成不存在的宣传图。
- `image_files` 顺序必须与 `[(0,N)](@img)` 的 `N` 完全一致。
- 图片缺失、空文件、占位符不连续或超过 50 张均为发布阻断错误。
- 只有上传层发生 EOF 时才生成压缩副本；原始素材和 hash 仍保留。

## 人工复核

以下情况设置 `requires_manual_review=true`：

- 无明确版本号
- 多个版本号
- 仅靠日期或最近发布时间归并
- registry 通过日期而不是版本命中
- 多个 registry 帖子同时匹配

人工复核应确认版本、发布日期、主题、图片语义、既有帖目标和最终标题。批准只解除对应的人工复核原因，不能忽略技术校验错误。
